Data Communication

Exploration vs. Communication

  • Exploratory plots are for you
    • Fast, messy, default labels are fine
  • Communication plots are for other people
    • They don’t know your data, so the plot has to explain itself
  • Today: two tools that make the jump easy
    1. Labels – say what the plot shows
    2. Annotations – point to what matters
  • Reference: R for Data Science, Ch. 11 – Communication

Annotations: Labeling Groups

Instead of a legend, put the label right next to the data

First, make a small data frame with where each label goes and what it says:

mpg_labels <- mpg |>
  group_by(drv) |>
  summarize(displ = mean(displ),
            hwy   = mean(hwy)) |>
  mutate(drive_type = case_when(
    drv == "f" ~ "front-wheel drive",
    drv == "r" ~ "rear-wheel drive",
    drv == "4" ~ "4-wheel drive"
  ))

mpg_labels
# A tibble: 3 × 4

  <chr> <dbl> <dbl> <chr>            
1 4      4.00  19.2 4-wheel drive    
2 f      2.56  28.2 front-wheel drive
3 r      5.18  21   rear-wheel drive
  • case_when(): “if this, then that” – recodes f / r / 4 into readable names

Annotations: geom_text()

  • Code
  • Plot
ggplot(mpg, aes(x = displ, y = hwy, color = drv)) +
  geom_point(alpha = 0.3) +
  geom_smooth(se = FALSE) +
  geom_text(data = mpg_labels,             # use the label data frame
            aes(label = drive_type),
            fontface = "bold", size = 5) +
  theme(legend.position = "none")          # legend no longer needed
  • Problem: labels sit on top of the lines and can overlap 😕

Annotations: ggrepel

geom_label_repel() pushes labels away from each other and from the data

  • Code
  • Plot
# install.packages("ggrepel")   # run once
ggplot(mpg, aes(x = displ, y = hwy, color = drv)) +
  geom_point(alpha = 0.3) +
  geom_smooth(se = FALSE) +
  ggrepel::geom_label_repel(data = mpg_labels,
                            aes(label = drive_type),
                            fontface = "bold", size = 5, nudge_y = 2) +
  theme(legend.position = "none")
  • package::function() uses a function without loading the whole package

Annotations: Highlighting Outliers

Same idea: filter the interesting points, then layer them on top

potential_outliers <- mpg |>
  filter(hwy > 40 | (hwy > 20 & displ > 5))
  • Code
  • Plot
ggplot(mpg, aes(x = displ, y = hwy)) +
  geom_point() +
  geom_point(data = potential_outliers, color = "red") +    # recolor them
  ggrepel::geom_text_repel(data = potential_outliers,       # name them
                           aes(label = model))
  • Each geom can use its own data = — this is the key trick for annotations

Annotations: annotate()

For a one-off note, skip the data frame and use annotate()

  • Code
  • Plot
ggplot(mpg, aes(x = displ, y = hwy)) +
  geom_point() +
  annotate(geom = "label", x = 3.5, y = 38, hjust = "left", color = "red",
           label = "Larger engines tend to\nhave lower fuel economy") +
  annotate(geom = "segment", x = 3, y = 35, xend = 5, yend = 25,
           color = "red", arrow = arrow(type = "closed"))
  • \n starts a new line in the text

Quarto

What is Quarto?

  • One file that combines code + results + writing
    • Change the data → re-render → every number and plot updates
  • The successor to R Markdown; works with R, Python, and more
  • Already built into RStudio
  • These slides (and the course website) are made with Quarto!

Anatomy of a .qmd File

---
title: "My First Report"
format: html
---

## Results

The `mpg` data has `r nrow(mpg)` cars.

```{r}
ggplot(mpg, aes(x = displ, y = hwy)) +
  geom_point()
```
  1. YAML header (between ---): title and output format
  2. Text written in Markdown (## heading, **bold**, *italic*)
  3. Code chunks (```{r}) that run and show their output

Try It

  1. RStudio → File → New File → Quarto Document…
  2. Paste in your plot from “Your Turn”
  3. Click Render
  4. Change format: html to format: revealjs (slides!) or format: docx (Word) and render again
